# The hive, card for card — design

Date: 2026-09-17. Status: approved by the user on the visual companion
(direction A "Studio", fidelity tier 2 with tier 1 fallback, three drops;
synchronized output and the gallery in the first drop). Mockups:
`.superpowers/brainstorm/23923-1789620273/content/{redesign-v1,fidelity-v1}.html`,
generated by `gen/mock.py` and `gen/fidelity.py` in that folder with the cell
renderer in `_build/tui-port/{canvas,palette}.py`.

Supersedes the pane sections of `docs/superpowers/plans/2026-09-16-tui-north-star.md`.
The transcript grammar, tab line, title row, composer and status row of that
document stay as designed there; this document is about *what the pane draws*
and *how faithfully the terminal can draw it*.

## 1. Why

The screen the user sees today has the structure of the September 15 port
(tab line, hive pane, Ctrl-R, Ctrl-G) and none of its surface: no filled cards,
unlit gauges, one line per agent, the run title three times, UUIDs in the
palette. The web app's swarm pane (`~/dev/swarm-code`, `SwarmCodeWeb.SwarmPane`,
read-only reference) is the model: one card per agent with avatar, status,
subtitle, run meta, tool chips, current task, gauge and controls; sub-agents as
mini cards; an operations drawer; a consensus bench; a lane timeline; a changes
ledger. This design ports that pane card for card.

## 2. Fidelity tiers

A terminal's pixel is the cell. Three tiers, chosen per session by
`Capabilities.glyph_tier`:

| tier | when | draws with |
| --- | --- | --- |
| `:measured` | default | glyphs that measure one cell under both width policies: `▐ ▗▖▝▘ ▰▱ ▬ ▪ ⬤ ⬡ ✦ ✳ ⋔ ⚖ ✓ ✕ › ◷ ⧉ ≣ ⎇ ↻ ▮` and braille |
| `:rich` | truecolor, narrow policy, not ASCII, and `TERM` names ghostty, kitty, wezterm or iterm | the measured set plus eighth blocks `▏▎▍▌▋▊▉█`, vertical eighths `▁▂▃▄▅▆▇`, half blocks `▄ ▀`, the dashed rule `┄` |
| ASCII | `ascii?` | the existing `_ascii` twins |

Every rich token has a measured twin and an ASCII twin; `Projector.Support.glyph/2`
resolves a token for the state's tier so projectors never branch on it.
Tier 3 (kitty graphics) is a later drop and not designed here.

Rich is safe only under the narrow policy: the rich glyphs are East Asian
Ambiguous and measure two cells under `:wide`. `from_probe/1` never selects
`:rich` when `ambiguous_width == :wide`.

## 3. Colour

The web's Carbon dark palette, hex for hex, already in `UI.Theme`. One new
role, `:text_ghost` (#4B4A48, the web's `color-mix(faint 72%)` over the
elevated surface) for hints that must read as background. Colour means one
thing: lane colour = whose work; status colour = how it ended (`Theme.status/1`,
`Words.role/1`); the accent = the assistant and focus; amber = you are needed;
`:run_consensus_judge` = judged.

A gauge takes the lane colour while the agent runs and the status colour once
it has settled (the web's own rule). At tier `:rich` under truecolor a running
gauge may carry a gradient from the lane colour into the accent; the painter
mixes per cell and the projector only names the two roles.

## 4. Scene blocks

Existing blocks keep their shape; the painter reads `Paint.Options.glyph_tier`.

- `Block.Surface` gains `edges: :corners | :half`. `:corners` is today's
  rounded quadrant frame. `:half` paints the top row as `▄` and the bottom row
  as `▀` in the surface colour over the outside colour (a half-row margin),
  with quadrant corners; at tier `:measured` it falls back to `:corners`. The
  accent rail stays `▐` (a left rail glyph is not narrower at one cell).
- `Block.Gauge` gains `style: :smooth` (eighth-block fill, eight steps per
  cell; falls back to `:ticks` at `:measured`) and `gradient_to: role | nil`
  (per-cell mix from `tone` to `gradient_to` at `:rich` + truecolor; ignored
  elsewhere).
- `Block.Chart` gains `style: :braille | :sparkline`; `:sparkline` is one row
  of vertical eighths at `:rich` and falls back to `:braille` height 1.
- New `Block.Columns{columns: [%{width: n, blocks: [...]}], gap: 1}`: each
  column is laid out to its width and the rows are zipped side by side, every
  line padded to its column with the inherited style. This is how the
  sub-agent grid and, later, the board direction are drawn.

Nothing changes on the wire: a glyph is text plus a projector-owned width.

## 5. The pane

Three tabs, `Agents · Timeline · Changes`, in that `[`/`]` order; the
`thread` tab is gone and the verdict card of a judged run lives in Agents.
The layer spelling `:overview` maps to `:agents`. The strip paints the current
tab bold on the hover surface and the waiting count as a solid amber bubble
after `Agents` when something waits for you.

### 5.1 Agents

At the dock's width `w` (38..56), top to bottom:

1. **Lead card** (`Surface`, accent = lane 1, or `:run_consensus_judge` for a
   judged run), rows:
   - head: `AGENT` label; right: `stop` action when `stop_agent` is allowed.
   - avatar: a 4×3 block on the hover surface holding `⬡` (lead), `⚖` (judge)
     or `✳` (assistant) in the lane colour; beside it the name in bold and the
     status right-aligned as `⬤ ACTIVE` in the status role (dot on the chip
     tint while running).
   - subtitle: `LEAD AGENT · <model>` (the run's model), or
     `ROUND n · JUDGING…` for a judged run with a live verdict round.
   - run meta: `<done>/<total> sub-agents done · <clock started> · <tokens> tok`,
     omitting what the read model lacks.
   - tool chips: the distinct tool names of this agent's tool items, at most
     three, then `+N`; `no tools yet` in ghost when none.
   - dashed divider (`▬ ` alternating at measured, `┄` at rich).
   - `CURRENT TASK` label, right: percent when progress is known.
   - gauge: `:smooth` with `gradient_to: :accent` while running, `:ticks` in
     the status colour once settled.
   - task: the agent's step, else the running operation's title, else the
     state in words; right: `LEAD <n> · SUBS <m>` when there are sub-agents,
     else `<n> TOKENS`.
   - foot: `◷ lanes` (Timeline tab), `⎇ diff` (Changes tab).
   A run without agents draws the assistant as the lead card, as the hive did.
2. **SUB-AGENTS** label; right `k of n done · m waiting` (never a zero).
   Grid of 5-row mini cards, two columns when `w >= 46` else one; each an
   action selecting the agent for the drawer:
   `✦ name` and the state mark right (`✓` done, `⬤` running on tint, `?`
   solid amber waiting, `✕` failed); `SUB · D<depth>` (+ ` · APPROVAL` /
   ` · FAILED` in colour); a gauge; `<tokens> TOK` left, `<ops> ops` right.
   Below ten agents the grid switches to one-line rows (today's lanes,
   restyled on a surface with a lane rail).
3. **OPERATIONS · <agent>** for the selected agent (default: the newest running
   sub-agent, else the lead): its tool and thinking items, newest last, one row
   each: family glyph in the family colour, name chip, argument (tool.detail
   or title), a 14-cell ticks gauge while running or a state chip once settled
   (`done`, `failed`), duration, `›` when a detail can be opened.
   Families: `run_command ⌘ accent`, `read_file/list_dir ≣ info`,
   `grep/search ⌕ run_goal`, `write/edit ✎ success`, `spawn ✦ run_swarm`,
   thinking `✳ text_faint`, else `▪ text_muted`.
4. **Verdict** (judged runs): the existing verdict card on a surface with the
   judge accent, after the lead card.
5. **Waiting for you** (when an interaction of this run is pending): a surface
   with the warning rail: `? <agent> wants to run a command` (or `asks a
   question`), `$ <arguments_preview>`, the permission in words, and the keys
   `y once · d deny · ↵ open`; the row is the existing `open_interaction`
   action.

Rows that do not fit are dropped from the bottom, sections before rows:
operations first, then the sub-agent grid degrades to rows, then chips.

### 5.2 Timeline (drop 2)

`LANES`: one row per agent, glyph and name, then a bar over the run's clock
from `started_at` to `finished_at` or now, lane colour while running, status
colour when settled, `?` at the end of a waiting lane. Then `OPERATIONS`
(today's event rows, with the agent's lane dot and the family chip), then a
`THROUGHPUT` sparkline of tokens per minute when there is room.

### 5.3 Changes (drop 2)

Today's ledger on surfaces: one card per file with the touching agent's rail,
the path with its extension in the file-type colour, the agent's name, the
time; the blast-radius line; commit and PR chips when the daemon offers them.

## 6. Synchronized output

`native/terminal_port/src/output.rs` brackets every painted frame in
`CSI ? 2026 h` … `CSI ? 2026 l` (DEC private mode 2026, synchronized update).
Terminals that do not know the mode ignore it; the ones the user runs
(ghostty, kitty, wezterm, iTerm2, foot) show the frame at once. The bracket
opens before the first dirty row and closes after the cursor is restored, only
when something was painted.

## 7. Gallery and golden renders

`mix swarm_code.demo.cells` already paints fixture states to SVG under
`_build/cell-previews/`. It gains the pane states (swarm agents, consensus,
waiting) at 170×42 in truecolor at both tiers, and the fixtures gain what the
cards need (tool items per agent, a pending approval). Every drop ends with
those SVGs and a real-terminal capture shown on the companion beside the mock.

## 9. Testing

- Every new token: a test asserts its width under both policies (`1/1` for
  measured and ASCII twins; `1` narrow for rich) and that the twins exist.
- Painter: cell-level tests for `Surface edges: :half`, `Gauge :smooth` (eighth
  boundaries), gradient mixing (first and last cell colours), `Chart
  :sparkline`, `Columns` zipping and padding, and the `:measured` fallbacks.
- Capabilities: `from_probe` picks `:rich` for `xterm-ghostty` + truecolor +
  narrow and not for `:wide`, ASCII or a 256-colour terminal.
- Projector: `inspector_cards_test` rewritten for the card layout at 170×34
  and 150×30, monochrome and ASCII: the lead card rows, the grid, the drawer,
  the verdict and waiting cards, the action table (select agent, stop, open
  interaction, tab switches). `keymap_test`'s `:thread` expectations move to
  `:agents`.
- Rust: an output test asserting the 2026 bracket around a painted frame and
  its absence around an unchanged one.
- Suites run from the umbrella root with `unset MIX_QUIET; mise exec -- mix
  test`; `mix format`; `mix swarm_code.keymap --write` when bindings change.

## 10. Out of scope

Kitty graphics (tier 3), mouse, Nerd Font icons, pane layout toggles
(tree/grid, full/compact) as user settings, per-agent pause, copy-to-clipboard
from the card, and the run-level turn counter (`turn n/m`), which has no wire
field.
