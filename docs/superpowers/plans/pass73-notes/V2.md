  (`"untrusted"`, `"read_only"`, `"no_provider"`, `"not_found"`; an unknown `snake_case` code reads as its

  `:rejected` mutation reads `state.mutation_reasons[origin]` (request K-1), else K's newest `:refused`

  `" · nothing asks first"` (the new mode's meaning) when `detail?`.
- `Projector.Composer.workflow_hint(state, width)` (T5): the row above the composer while the draft routes
  to `/create-workflow` (`workflow · sends as /create-workflow · Ctrl-S plain message`); it wins over the

- The slash popup's selected row says `Enter run` / `Enter complete` (K's `enter_action`), `Tab complete`

## Requests

### K-1 (K, `ui/reducer/commands.ex` + `ui/state.ex`): keep the refusal reason of a settled mutation

The status toast needs why a request was rejected; today the reducer keeps only the status. Add a state
field `mutation_reasons: %{}` (origin → reason) and, in `Reducer.Commands` where the outcome settles
(`mutations: Map.put(state.mutations, request.origin, {:settled, request.request_id, outcome.status})`):

```elixir
mutation_reasons:
  case outcome do
    %{status: status, error: %{code: code}} when status != :accepted ->
      Map.put(Map.get(state, :mutation_reasons, %{}), request.origin, code)

    _ ->
      Map.delete(Map.get(state, :mutation_reasons, %{}), request.origin)
  end
```

When S publishes a typed refusal reason on the wire (a binary code or words), store that instead of the
`AdmissionError` code; `Status.refusal_words/2` takes either.

### K-2 (K, `native/terminal_port/**` + a V2 owner change): `/mouse` live

The owner ignores `mouse?` in `{:terminal_preferences, …}`: the port has no mode command, and the owner's
`ready` check compares its `flags` with the port's reported bits (a flipped flag without the port would
fail the next resume). If K adds a wire op (e.g. `<<1, 8, generation::64, token::64, mouse>>` answered by
a record), the owner change is: in `dispatch({:terminal_preferences, p}, state)`, when
`Map.has_key?(p, :mouse?)` and it differs from `state.flags.mouse?`, send the op with a control token and
set `flags.mouse?` only when the port confirms. Until then `/mouse` applies at the next launch (cli.json).

### K-3 (K, init): `state.theme_mode` must start as the painted theme

The port owner starts in `Theme.mode(env, cli_json_theme, settings_mode)` (the launcher). `state.theme_mode`
must be initialised to the same value, or the first `/theme` flips the state to the theme already on
screen and nothing changes. Use `Theme.mode/3` in the launcher and init alike, and `Theme.switch_words/2`
for the confirmation.

### K-4 (K, `ui/request_resolver.ex`): a compile warning from the tag

`mix compile` warns "clauses with the same name and arity … defp valid_origin?/2 was previously defined
(request_resolver.ex:193)" at line 210: group the `valid_origin?/2` clauses (precommit compiles with
`--warnings-as-errors`).

### K-5 (K, reducer): the policy-change toast

Use `Projector.Status.policy_words(from, to, true)` for the toast
("Approvals: auto → full access · nothing asks first") and V1 uses `policy_words(from, to)` for the
transcript notice, so both read the same.
