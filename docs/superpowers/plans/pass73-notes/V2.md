# Pass 73 notes: owner V2 (chrome)

## Published

- `Projector.Status.composer_hints(state) :: [{key_label, words}]` (T6): the composer's hints, strongest
  first; the status row takes as many as fit. `Status.enter_words/1` maps K's `enter_action`
  (`send`, `steer`, `queue`, `run`, `complete`; nil for `:none`); `Status.esc_words/1` says what Esc does
  ("stop Workflow author", "close"), nil when it does nothing.
- `Theme.mode(env, cli_json_theme, settings_mode)` (T2): `SWARM_THEME` > cli.json > desktop settings >
  dark (unknown values fall through). `Theme.mode/2` is the same without cli.json. `Theme.env_mode/1`,
  `Theme.switch_words(mode, env)` → `"Theme: light · /theme switches back"` plus
  `" · SWARM_THEME=dark still wins at the next launch"` when the env forces the other theme.
- The port owner handles K's `{:terminal_preferences, %{theme: :dark | :light}}`: the next frame paints in
  that theme and the kept (degraded-fallback) frame is dropped. `mouse?` in the same message is ignored
  by the owner (see request K-2).
