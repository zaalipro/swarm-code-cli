## Requests

### V2 — `ui/projector/composer.ex`, `Composer.edge/2` (T7: the card never touches the composer)

The card no longer puts its keys on the edge row. Let the edge row stay the composer's own
(HiveStrip or the hairline with the queued label) whenever the card says so:

```elixir
  def edge(state, rect) do
    width = rect.width

    case ApprovalCard.layout(state, width) do
      %{edge: :composer} ->
        HiveStrip.block(state, width) || hairline(state, width)

      %{rows: rows, growth: growth} ->
        {left, right} = Enum.at(rows, growth)
        row(left, right, if(growth == 0, do: :approval, else: :approval_body), state, width)

      nil ->
        HiveStrip.block(state, width) || hairline(state, width)
    end
  end
```

Until this lands the edge row draws V1's plain hairline on the card surface (a grey strip under
the blank row). `Composer.card_blocks/3` is no longer called by V1 (Workspace draws the card with
`ApprovalCard.block/3`); it can go.

### K — Enter shows all (T7: "… N more lines · Enter shows all")

While the top layer is `{:approval, id}` and the draft is blank, Enter toggles
`state.selection["approval_all"]` between `id` and absent (the card then shows every command line,
paged with PgUp/PgDn through the existing `dialog_scroll`). Today Enter there activates the focus
"cancel" and closes the card. Suggested: only when `ApprovalCard.hidden_lines(state,
Layout.for_state(state).rects.main.width) > 0` or the card is already expanded; otherwise keep
today's behaviour. `Composer.enter_action/1` may name it `:show_all` for V2's footer ("Enter shows
all").

### K — a letter typed on an open card is eaten (seen live, pass73 sandbox)

With an approval card open (top layer) and a blank draft, typing the sentence "Also add the word
ok after the number." put "lso add the word ok after the number." in the draft and the card went
away until Ctrl-N (the `A` was taken as a card key although `A` was not an allowed decision there,
and the card was put aside). A key that is not one of the card's `allowed_decisions` should go to
the draft and leave the card open; a card key should only act while the draft is blank (as
today). A message starting "yes …"/"do …" typed on a blank draft decides the card, which is by
design but worth a hint.
