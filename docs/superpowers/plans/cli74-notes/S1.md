## Contracts published at `c74-S1-wire` (client side)

- `Request.settings_query(params, origin, deadline)` / `settings_command(command, origin, deadline)`
  return the unvalidated shell (`request_id`, `scope`, `generation` nil) — the reducer fills them;
  the 4-arity forms take `request_id:`, `generation:` (the shell watch's) and optional `scope:` and
  return `{:ok, request} | {:error, {:too_long, param}} | {:error, :invalid_request}`.
  Params may use atom or string keys; missing keys are filled (`attributes` `%{}`, `secrets` `[]`,
  `dry_run` false, the rest nil). Scope is always `Request.settings_scope(generation)` (global).
  `Request.settings_violation/1` names the parameter outside its bound; `Request.too_long_words/1`
  gives `That is too long to save here (<param>)`. Origin: `{:settings, generation > 0, purpose}`
  (purpose: atoms/integers/strings ≤ 512 bytes, tuples/lists ≤ 8 items, depth ≤ 3).
- Effects: `{:query, settings_query_request}`, `{:command, settings_command_request}`.
- Deliveries (`{:swarm_code_ui_data, epoch, %Delivery{kind: :response, body: …}}`):
  `%DTO.SettingsSnapshot{request_id, view, revision, available, message, body}` (view atoms:
  values overview facts usage open task records record file; body: `SettingsValues{values:
  [SettingValue], project_id, conversation_id}`, `SettingsOverview{attention, glance}`,
  `SettingsFacts{paths, database_bytes, env, versions, research_levels, scheduler}`,
  `SettingsUsage{spend_usd, budget_usd, by_model}`, `SettingsOpen{values, overview, facts, projects}`,
  `SettingsTaskView{task_id, action, target, state, elapsed_ms, message, summary, rows, next_cursor,
  total}`, `SettingsRecordPage{kind, items: [SettingsRecord], next_cursor, total}`,
  `SettingsRecord{kind, id, fields}`, `SettingsFile{fields, content}`; nil when `available` false —
  a query error (e.g. `that result is gone; run it again`) is `available: false` + `message`),
  `%DTO.SettingsResult{request_id, status, results, record, task, message, confirm, field_errors,
  revision, corrective_action}`, or the tuple `{:settings_failed, request_id, words}` (a refused
  answer, a data-source failure, a deadline; a command whose fate is unknown says
  `Couldn't tell whether that was saved; reloading.`).
- `SettingValue{key, value, layers: [%{layer, value, set, ignored, raw, source, note}], winner,
  writable, base, choices: nil | [%{value, label, hint}], state: :ok | :invalid | :attention, note}`;
  layers/winner/writable are atoms (flag env session project cli global project_file default).
  Record fields keep string keys; a secret field is `%{set: boolean, hint: nil | "abcd"}`; an MCP
  env/header list is `[%{name, secret, value, hint}]`. Record fields not declared in the kind's
  `RecordKind` are dropped (debug log), so a field S2/U2 add must be declared in `records.ex`.
- Deltas on the shell watch: `%Delta{kind: :settings_update, body: %DTO.SettingsUpdate{revision,
  sections: [section atoms], origin: :settings | :elsewhere}}` (entity_id nil) and
  `%Delta{kind: :settings_task, entity_id: task_id, body: %DTO.SettingsTask{task_id, action, target,
  state, elapsed_ms, progress: nil | %{done, total, bytes, step}, summary, message}}`.
- Fake: `Source` takes `settings: [auto_tasks:, integrations: false, env:, flag_model:, now:]`;
  controls in `Fake.Settings` (`put/3`, `fail_next/3`, `hold_task/2`, `release_task/3`,
  `reply_outcome_next/2`, `stub_reply/3`, `requests/1`, `secret_writes/1`, `step/1`, `state/1`)
  accept the source or the client adapter; `Fake.step/1` = `Fake.Settings.step/1`. Stub replies:
  a result map (atom or string keys) or `{:task, summary}` / `{:task, summary, rows}`.
  U2's `Fake.SettingsIntegrations` is used when present (a plain call, rescued when the module
  is absent — `Code.ensure_loaded?` is forbidden in the CLI lib by the architecture test); its
  state lives under `:integrations`.

  `Context.sessions_store`, `TaskSpec.target`/`holds_secrets?` added (additive).

- `Request.settings_query/3` returns the unvalidated shell; the completed form is 4-arity (the

  settings answer passes `Delivery.validate/1`.
- A query error is an unavailable snapshot (`available: false`, `message`) — the snapshot has no
  status field.
- Commit prefix `cli74 S1-n` (the orchestrator's rule) instead of §5.0's `pass74`.
- `WireBounds.actions/0` is the closed action list; `lsp.restore_key` is not in it (U2 asked; S2 agrees).
- `Values`: a retry whose value is already in place answers `unchanged` before the compare-and-set
  check (a lost reply retried with the old `expected` is not a conflict).
- `Values` reads the project file itself; the facts' database path comes from `Repo.config`.
- `SessionConfiguration.usable?/1` (D11's one predicate) landed in S1-8, not S1-10.
- The S1-9 commit also carries the backend's settings job path (the pool, query keys, command
  jobs); S1-10 added the deltas, D11 and the LiveBackend.
- `Tasks.view/2` answers `{:ok, body, tasks}` (the view touches the LRU), not `{:ok, body}`.
- `task.cancel` is answered by the backend inline: `accepted`; `unchanged` + `That already
  finished.` for a finished or unknown task; `rejected` + `this cannot be stopped once it started`
  for a non-cancellable one.
- D11 is checked in `start_turn` only (the dispatch a user sends); queued starts that were admitted
  before a key was removed are not re-checked.
- The workspace metadata carries `chat_provider_usable` (boolean, optional; `chat_provider` stays
  the provider's name) instead of §3.10.1's `chat_provider: %{name, usable}`: the name field is a
  string that `ModelPicker` already reads, and changing its type would break it.
- The lease words name the process (`A swarmcode session is open (process 4242); …`) rather than a
  directory: the lease records the pid, not the session's folder.
- `swarmcode settings`: the query is at most 200 bytes (the reducer's `Event.open_arg?/1` bound);
  the launcher and `Release.parse/1` refuse a longer one (`the settings query is too long (200
  bytes at most).`, exit 2) and `PersistedSession.settings_open/0` turns any query the reducer
  would refuse into `""` (the Overview) so the boot never raises `invalid reducer init`.
- A settings-only session ignores cli.json's `startup_conversation` and opens the latest
  conversation (`new` would start an empty conversation at every `swarmcode settings`, and `ask`
  would put the resume picker over the settings layer).
- `swarmcode config export` writes records only with `--include-records` and refuses an existing
  file (no overwrite flag in §3.10.3's grammar); the TUI's export may overwrite (`overwrite`).
- `swarmcode config` record verbs call S2's handlers; on this branch alone they answer
  `unsupported` (exit 1).
- `mcp.reconnect`'s subscribe-then-wait (§3.3.8 rule 4) is inside S2's handler, not the backend.
- `docs/keybindings.md` is untouched (no binding changed in S1's files).

## Contracts added after `c74-S1-wire` (service, backend, launcher)

- **Settings jobs** (`SVC/settings/jobs.ex`, `Settings.Jobs`): a pool of 4 per backend. Queries are
  keyed `{:settings_query, view, kind, id, project_id, slot}`; a new query with the same key
  replaces the older (it answers `stale_revision`); a 5th job is `capacity_exceeded` (query) or a
  `busy` settings_result `Settings is busy; try again in a moment.` (command, no ledger row). A
  query job's timer is the request timeout; a command job's is `max(timeout − 1000, 1000)`.
- **Commands and the ledger**: a command with pasted secrets is neither durable nor remembered (a
  retry re-runs it); its fingerprint masks secrets as `"[secret]"`. Every settle path (answer,
  crash, timer, backend stop) completes the ledger row; one without an answer completes it with an
  `unavailable` settings_result `Couldn't tell whether that was saved; reloading.`. Results are
  guarded to 120 KiB before `CommandLedger.complete/3` (status kept, rows dropped).
- **Tasks** (`SVC/settings/tasks.ex`): at most 8 running (`Eight settings checks are already
  running; wait for one to finish.`); the same key replaces a cancellable task, and a
  non-cancellable one blocks it (`That is still running; wait for it to finish.`). A cancellable
  task past its timeout stops (`no answer in N s`); a non-cancellable one reports `still running
  after N s`. `ProbeRunner` stops a probe and kills its OS process tree. Progress deltas are ≤ 4/s.
  Messages are redacted (`HTTP.redact/2`, `/1`, then secrets shorter than 8 bytes), cut to 2 048
  bytes; summaries are ≤ 16 KiB or nil.
- **Task cache reads** (`ctx.task_results`): a map keyed `{action, key}` for `{action, :all}`
  (entries without `result`), `{action, target}` for `:target`, and `{action, task_id}` for
  `{:param, name}` (`name` is looked up in params, `attributes`, `options`, then `target`). Entries
  are atom-keyed `%{task_id, action, target, state, at, elapsed_ms, summary, result, message,
  secret?}`. `{_, :sessions_store}` fills `ctx.sessions_store`.
- **The sessions store**: `storage.measure`'s `result["sessions"]` goes to the sessions store, not
  the LRU, and leaves the cached result.
- **Secrets-bearing results** (`holds_secrets?: true`: an import preview, `mcp.import.read`) keep
  their raw result for the apply, are purged after 10 minutes, and their task view shows the rows
  and the handler's summary only (never `drafts` or any other key). Result keys starting with `_`
  are private to the task (the import preview's parsed file) and never shown.
- **Deltas on the shell watch** (no `conversation_id`): `settings_update` is coalesced over 100 ms
  from the settings, providers, search, projects and storage topics (and MCP status). Its origin is
  `settings` within 1 s of this session's own accepted command, else `elsewhere`. A conversation
  change to a model or effort column marks `models_effort`.
- **D11**: `start_turn` refuses with `{:provider_required, words}` (wire `not_allowed`):
  `No model provider can answer: <name> has no key. Add one in /settings providers.` (or `No model
  provider can answer. Add one in /settings providers.`). The workspace metadata carries
  `chat_provider_usable`.
- **LiveBackend** (a session run from `SWARM_*` variables): a query answers an unavailable
  snapshot and a command an `unavailable` result, both with `Saved settings are available in a
  saved session (swarmcode). This session runs from SWARM_* variables.`.
- **FeatureRequest**: `canonical_messages/0` and `message/1` for the four closed codes.
- **Export v1** (`SVC/settings/transfer.ex`): `{"format": "swarmcode-settings", "version": 1,
  "scopes", "global", "project", "terminal", "providers", "search", "mcp_servers", "pricing",
  "lsp", "desktop_keys"}`. Model values name their provider (`{"provider", "model"}`). A secret is
  `"<secret: set>"` or null, MCP values are masked unless `mcp_plain_values` (a secret-looking pair
  is always masked), and the file is written 0600 and atomically. The import preview's rows are
  `{id, scope, key_or_record, now, after, status: change|same|invalid|secret_skipped, message}`;
  the apply resolves providers by name, and an imported search engine that needs a key stays off
  (`paste the key after import, then turn it on`).
- **Doctor** rows `{id, ok, message}`: `database`, `config_dir`, `provider:<name>`, `mcp:<name>`,
  `search`, `project_file`, `research_root`; the summary is `{ok, failed}`.
- **Headless** (`SVC/settings/headless.ex`): `project/1`, `conversation/2`, `context/2`,
  `command/3` (a task runs to its end in the caller), `run_task/2`.
- **`swarmcode config`** (`REL/config_command.ex`): the verbs of §3.10.3. Secrets come from stdin
  only. Exit codes: 0 done or unchanged, 1 other, 2 usage or an invalid value, 3 startup refused,
  4 conflict. It boots the foundation only (`PersistedSession.with_foundation/2`).
- **Launch** (`REL/persisted_session.ex`):
  - `launch/4` calls U3's `TerminalPreferences.launch/4` when it is loaded, else today's rules in
    the same map.
  - `put_accent/1` is called when `Theme.put_accent/1` exists.
  - `launch_facts/3` gives `%{env_overrides, flag_overrides, flags, project_root, log_path,
    cli_path, cli_version, home}`.
  - `tui_selection/0` and `startup_selection/1` implement cli.json's `startup_conversation`
    (`ask` → `{:latest, true}`).
  - `settings_open/0` gives nil outside settings mode, else the query (`""` means the Overview).
  - The Init fields set through `struct/2`: `settings_open`, `prefs`, `launch_facts` and
    `resume_picker?`.
- **Docs**: `mix swarm_code.settings --write` regenerates `docs/settings.md`; `--check` fails when
  it is stale (a test runs it).
- **Test seams** (app env, test only): `:settings_job_seam` (`fn kind, params -> :continue |
  {:answer, answer}`, run in the job process) and `:settings_values_seam`.
