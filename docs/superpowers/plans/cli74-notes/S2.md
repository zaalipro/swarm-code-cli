## Shapes every S2 handler answers

- Bodies and records use string keys. A record is `%{"kind", "id", "fields"}`; a page is
  `%{"kind", "items", "next_cursor", "total"}` (`next_cursor` = the next offset as a string,
  page size ≤ 200). Every record field is declared in `CORE/settings/registry/records.ex`
  (`C74S2.declared!/1` checks each handler's records the way the client decodes them).
- Nested `{:records, sub}` fields (provider `effort_levels`, efforts `builtin_levels`/`presets`,
  `mcp_server.tools`, project-config `profiles`) are lists of **plain field maps**, not
  `{kind, id, fields}` records — what S1's `settings_decode.ex` `field!/4` reads
  (`fields!(sub_kind, row, max)` per row).
- `Result.results` rows are atom-keyed `%{target, status, value, current, message}`
  (`Result.row/3` shape); field errors `%{target, message}`. Business refusals are
  `%Result{status: :rejected, message}` (`turn it on first`, `set a retention first`, built-in
  files, …); bad input is `%Error{code: :invalid}` with field errors.
- **Attention items** are atom-keyed `%{id, severity, section, target, title, reason}`:
  `id` is the §2.1 code only (`"AT2"`) — several items may share it, `(id, target)` is unique;
  `severity` is `"error" | "warning"`; `section` a `Sections` id (`providers`, `pricing`,
  `search_web`, `mcp`, `project_file`, `approvals`, `library`); `target` is
  `%{"kind", "id"}` or `%{"key"}`. `Wire.json/1` turns them into the overview's wire items.
- **Glance fragments** (numbers and strings only, ≤ 16 entries, nils dropped — `Kit.glance/1`):
  `providers {count, usable, answered, failed, never_tested}`, `search {engines, on, first,
  reader, failed}`, `mcp {servers, on, ready, failed, tools}`, `storage {retention_days,
  prune_days, last_sweep, sessions_measured, cleanup: "running"|"idle"}`.
- `ctx.task_results` entries are read with atom or string keys (`task_id, state, at, summary,
  result, message`); states `done`, `failed`, `timeout`, `cancelled`.

## Requests for other owners

### S1 — backend tasks (S1-9/S1-10)

1. **`plan_id` / `import_id` are task ids the handler cannot know.** `storage.run` reads the plan
   with `Kit.task_entry(ctx, "storage.plan", plan_id)` and `mcp.import.apply` the drafts with
   `Kit.task_entry(ctx, "mcp.import.read", import_id)` — both match the entry's `task_id`. The
   backend should put the task id into the summary it sends as `plan_id` (storage.plan) and
   `import_id` (mcp.import.read), or the client uses the `task_id` (U2 already does).
2. **`mcp.import.read` holds secrets.** Its `TaskSpec` has `holds_secrets?: true`. The result's
   `"drafts"` is a Base64 of the parsed JSON **including secret values** (Base64 so a
   string-walking redaction — rule 6 — cannot mangle it). Please: never send any result key but
   the paged `rows` (view=task), arm the 10-minute purge, and do not store a redacted copy in
   place of the result (the apply would then store `[REDACTED]`). `rows` carry masked env/headers
   only.
3. **The sessions store** is `result["sessions"]` of `storage.measure` (string-keyed
   `storage_session` fields; `updated_at` ISO text). `records:storage_sessions` and `storage.plan`
   read `ctx.sessions_store` (a list, atom or string keys) and answer `not_found`/`measure first`
   when it is nil.
4. `Settings.Storage.command("storage.plan")` keys the task `:wizard` (an atom, per §2.18);
   every other S2 key is a string.

### S1 — `CORE/settings/secret_pattern.ex`

### U2 — the integration pages (answers to U2's notes)

- `last_test` / `last_fetch` are `{state, at, count, ms, message}` (§2.23), not `{status, …}`.
- `pricing_row.derived_cache_read/derived_cache_write` are **numbers** — the rate a blank cell
  bills at (`Pricing.cache_read_rate(%{}, model, input)`, `cache_write_rate(%{}, input)`), not

- `lsp.restore_key` does not exist (the §3.4.3 action list is closed and `WireBounds.actions/0`
  refuses anything else); `x` on an unknown `lsp_servers` key stays not undoable.
- `mcp_server` summaries also carry `command` and `url` (declared fields) for the row's detail.

## Deviations (reported, not silent)

1. **New S2 helper file** `SVC/settings/kit.ex` (`Settings.Kit`): the frame shapes, paging,
   CAS compares, changeset errors, redaction/cut, task-cache reads, `home/0` and `glance/1` every
   handler shares. Not in §3.1's S2 row; S2 owns it.
2. **Test seams (app env, test-only):** `:settings_home_dir` (`Kit.home/0`: the home folder a
   typed `.mcp.json` path is confined to, and `~` in paths) and `:settings_user_agents_dir`
   (`Files.user_agents_dir/0`; the domain's `Agents` reads `System.user_home!/0`, which ignores
   `HOME` changes). Both default to the real home.
3. **MCP writes** compare-and-set and update the row inside the transaction, then do what
   `MCP.update/2` / `MCP.delete/1` do besides the row — `stop_client`, `start_client` when
   enabled, `broadcast` — after the commit, instead of calling `MCP.update/2` inside the
   transaction (it starts processes, and `Repo.retry` may re-run the transaction). The slug
   collision check is replicated with the domain's exact words. `mcp.create` calls
   `MCP.create/1` as specified.
4. MCP env/header field errors are keyed by list index (`env[2]`, `headers[0]`) — an invalid
   name cannot key its own error.
5. `Secrets.check_paste/1` also refuses non-printable text: `that does not look like a key`.
6. `Secrets.redaction_list/1` also lists the token of a `Bearer <token>` / `Basic` / `Token`
   value, so a reason that quotes the bare token is redacted.
7. `provider.apply_models` declares only `{"provider.fetch_models", {:param, "fetch_task_id"}}`
   (S1's Router table); `fetch_all`'s result carries counts only (§3.5.1), so there is no list to
   apply from it.
8. `file.create` is implemented by `Library.create/2`, called from `Files` (the Router sends
   `file.*` to Files).
9. `storage.apply_retention` stamps `storage_last_cleanup_at` **after** `run_sync/2` (as §3.5.5
   says); the domain's own sweep stamps before.
10. AT5's reason lists three models then `+N` when more are unpriced.
11. The daemon app has no StreamData (a `swarm_code_cli` test dependency); the secrets
    "properties" are seeded loops of 400 samples.
12. The `file` view answers `{"file": <file record with "content">}`; `file.save` results carry
    the record without content plus `parse` (`ok` or the parse error).
13. The c74 S2 fixture (`test/support/c74_s2_fixtures.ex`) adds two recent conversations so
    Appendix A's "unpriced in use" (`claude-sonnet-5`, `qwen3-coder`) holds under §3.5.2's rule.
