## `UI/data_source/fake/settings.ex` (S1) — how to dispatch to `Fake.SettingsIntegrations`

`SwarmCodeCLI.UI.DataSource.Fake.SettingsIntegrations` is pure. Its contract (string-keyed,
wire-shaped maps, exactly what the service would put on the socket before the codec decodes it):

- `seed(opts) :: state` — the Appendix A integration state (`:now`, `:env`, `:defaults`).
  Keep it in the Fake.Settings store, e.g. under `:integrations`.
- `handles?(action)` / `actions/0` — the 49 S2 actions of §3.4.3 (the list has 57 names in
  total; §3.4.3's "(60 actions)" is a miscount).
- `command(state, %{"action", "target", "attributes", "expected", "secrets", "dry_run"})` →
  `{{:ok, result}, state}` or `{{:task, task, result}, state}` or `:unsupported`.
  `result` = the `settings_result` value without `request_id`/`revision`/`task` (add them);
  for `{:task, …}` start a generic task from `task` (`"action"`, `"target"`, `"attributes"`,
  `"cancellable"`), put its `task_id` into the task map, and answer `result` + `task`.
- `run_task(state, task_with_task_id, :run | {:ok, summary} | {:error, message})` →
  `{{:done, summary, rows} | {:failed, message}, state}`: `:run` when the lifecycle finishes
  it (`Fake.step/1`, `auto_tasks: true`), `{:error, m}` for `release_task(fake, action,
  {:error, m})`. `rows` are what `view=task` pages. For `provider.set_key`/`search.set_key`
  a refusal answers `The new key was refused (<m>).` and keeps the stored key.
- `query(state, params)` → `{:ok, body} | {:error, status, message} | :unsupported` for
  `records`/`record` of `record_kinds/0` and the `file` view.
- `cancellable?(action)`, `check_paste/1`, `hint/1`, `usable?/1`, `secret_kv?/2`,
  `search_label/1`, `presets/0`, `fingerprint/1` are public helpers.

A pasted secret is never stored by the fake: only `{set, hint}`.

## `UI/settings/{op,reducer,layer}.ex` (U1) — ops, options and verbs the U2 sections return

Sections return plain op tuples; the ones below are not in `Op.t()` yet. Until they are, the
reducer drops them (`Op.valid?/1`); please add them (or tell U2 the names you prefer).

New ops:

- `{:draft_put, kind, fields}` — merge `fields` into the layer draft `kind` (create it when absent).
  Drafts used: `provider`, `pricing_row`, `effort_levels`, `mcp_server`, `mcp_import`,
  `storage_cleanup`, `library_new`.
- `{:draft_discard, kind}` — drop the draft (and its pasted secrets).
- `{:stage, {kind, id}, fields}` / `{:unstage, {kind, id}, [field] | :all}` — D8 staged fields
  (`layer.staged[{kind, id}]`); MCP connection fields and the provider delete page use them.
- `{:row_error, row_id, message}` — `layer.row_errors[row_id]`, cleared on the next edit of that row.
- `{:treat_secret, {kind, id, map, name}}` — the `s` *treat as secret* mark for this session
  (`layer.treat_secret`, a MapSet).
- `{:conflict_discard, {:file, ref}}` — Esc on a file conflict (§3.7.9): drop `layer.file_conflicts[ref]`.
  The Memory page reads `layer.file_conflicts[ref] = %{"mine" => text, "fingerprint" => fresh}`.

Command options (`{:command, action, target, attrs, opts}`) beyond `expected/write_key/secrets_from/undo/toast`:

- `secrets_from: :paste | {:draft, kind}` — the secrets of the command come from the paste
  target or from the draft's pasted values (`draft.secrets[slot]`), never from `attrs`.
- `after:` what to do on `accepted`: `:back`; `{:open_record, section, kind, then: [ops]}` (ops may
  use `:record_id` for the created id); `{:discard_draft, kind}`; `{:discard_draft, kind, then: :back}`;
  `{:unstage, {kind, id}, :all}`; `{:task, action, target, attrs}` (re-run a check).
- `errors_to: {:draft, kind}` — put `field_errors` of a `rejected` result into `draft.errors`.
- `undo: false` for record/file/secret writes (§3.7.10), or an inverse op.
- `write_key` shapes: `{:record, kind, id, field | atom}`, `{:file, ref}`, `{:file_create, kind, name}`,
  `{:setting, "lsp_servers", key}`.

Paste targets (`{:paste, map}`) carry `row_id, action, target, attributes, slot, label, set?,
kind, expected, then` and, for import variables, `draft: "mcp_import"` with `action: nil`
(the pasted bytes go into `draft.secrets[slot]` and travel with the later apply command).

Pickers: `on_pick: {:section, section_id, tag}` → the layer calls
`Section.picked(ctx, tag, value)` (MCP and Library implement `picked/3`); the ModelPicker and
the Providers/Pricing pickers answer through `commit(ctx, %{id: "picker:<picker id>", target: …}, value)`;
`on_pick: {:project, :page}` sets `layer.page_project_id` and reloads.

Verbs sections match on (please bind them in §3.9.2 contexts where missing): `:open_row`,
`:add` (a), `:add_key` (+), `:test` (t), `:fetch` (f), `:delete` (x / D / C), `:alt` (s / e),
`:save` (Ctrl-S), `:move_up`/`:move_down` (K/J), `:toggle` (Space), `:cancel_task` (c),
`:reset` (r), `:restart` (R), `:all_on` (A), `:all_off` (N), `:open_related` (o), `:copy` (y),
`:new` (n), `:step` (←→), `:next_tab`/`:prev_tab` (Tab/Shift-Tab inside the cleanup wizard),
`:escape` (Esc on a sub-page: the section answers first; `:default` = the normal back; `[]` =
ignored, e.g. while a cleanup runs), `:leave` (leaving a record page: the MCP page returns the
one `mcp.update` of its staged fields), `:external` (Ctrl-X), and the import variable
choices `:var_shell`/`:var_paste`/`:var_literal` (v/p/k — not bound in §3.9.2; Enter opens a
picker with the same three choices meanwhile).

Tasks in the layer: the cleanup wizard drops a stale plan by comparing the newest
`storage.plan` task's `attributes["selection"]` with its draft's selection and the summary's
`plan_id` with the task id — please keep `attributes` on the layer's task entries.

Row ids U2 uses: `rec:<kind>:<id>`, `fld:<kind>:<id>:<field>`, `key:<setting key>`,
`act:<action>`, `item:<list>:<name>`, `kv:<map>:<i>`, `file:<ref>`, `head:<group>`,
`info:<name>`, `link:<target>`, `new:library`, `picker:<picker id>` (a picker's result row).

## Deviations

- `UI/settings/integration_rows.ex` (`SwarmCodeCLI.UI.Settings.IntegrationRows`) is a U2 helper
  outside §3.1's list: the shared row builders, context accessors, task words and number
  formats of the eight U2 pages (so each section stays pure and small). U2 owns it.
- `UI/settings/key_value_secrets.ex` and `UI/settings/mcp_import.ex` are U2 sub-page modules
  (the MCP env/headers page and the `.mcp.json` import preview) rather than a KeyValue editor
  inside U1's editor set: the entries are staged with the other D8 connection fields and secret
  entries become paste targets, which an editor cannot express.
- Rows are plain maps with the `%Row{}` field names (and `R.new_page/3`, `R.confirm/1`,
  `R.picker/1` build plain maps with the struct field names) because `c74-U1-api` was not
  tagged while U2 worked; switching them to the structs is a one-line change in
  `IntegrationRows.row/1` (`struct(Row, …)`), `new_page/3`, `confirm/1` and `picker/1`.
- The sections do not `use SwarmCodeCLI.UI.Settings.Section` yet (same reason); every callback
  of §3.7.2 is implemented (`id, loads, rows, record_rows, sub_rows, act, commit, title,
  attention, counts`, plus `picked/3` where pickers are used).
- `c74-S1-wire` was not tagged either; the fake is not dispatched from `Fake.Settings` yet —
  see the dispatch contract above.
- Editors named in rows that U1 owns: `Editors.Text`, `Editors.Enum`, `Editors.Number`
  (`nullable, null_label, unit, quick`), `Editors.Multiline` (`loading`), `Editors.LspCommand`
  (`value, default, max`); `ModelPicker` is U2's.
