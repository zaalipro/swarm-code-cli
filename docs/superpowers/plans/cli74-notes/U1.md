## Contracts (what U2, U3 and the finisher can rely on)

- **Sections.** `use SwarmCodeCLI.UI.Settings.Section, id: …` gives the defaults. Callbacks:
  `loads/1 rows/1 record_rows/3 sub_rows/2 act/3 commit/3 title/1 attention/1 counts/1`, and
  (additive, optional) `picked/3` (a picker with `on_pick: {:section, id, tag}`),
  `confirm_external/3` (see below) and `filter/3` (see below). A module that is not in the build
  falls back to the defaults (`Sections.optional/3` recognises the `UndefinedFunctionError` that
  names exactly that module and callback; the UI never loads code by name).
- **Rows.** `%Row{}` or plain maps with the same field names (`Normalize.row/1`); pages, confirms
  and pickers likewise. `Rows.scalar/2` builds a registry row; `Rows.registry/2` a section's
  registry rows with its `danger` group.
- **Ops** (`Settings.Op.valid?/1` accepts every op `Ops.one/2` handles): `patch reset
  reset_section command task cancel_task load open back section confirm picker paste edit
  {:edit, row_id, opts} external_edit cli_write (an empty change set rewrites the file)
  open_folder copy toast leave project draft_put draft_discard stage unstage row_error
  treat_secret conflict_discard`, and new at `-3`: `{:goto, {:section, id} | {:key, key} |
  {:record, kind, id}}` (as the search's `g`) and `{:search, words}` (the search row with words).
- **Command options:** `expected write_key secrets_from (:paste | {:draft, kind}) after errors_to
  undo toast paste (:keep | :drop)` and, at `-3`, `confirm_with: {section, %{content,
  fingerprint}}` — set by the layer on the `file.save` of a text the user's editor returned; a
  `needs_confirmation` answer calls that section's `confirm_external(ctx, spec, items)` and runs
  the op(s) it returns (U3's Project file); without it the status line says the service's words.
- **Verbs** a section's `act/3` sees: Enter is `:open_row`; ←/→ are `:step` on rows whose keys
  list `:step`; the rest by name (`:add :add_key :test :fetch :delete :delete_record :alt :save
  :move_up :move_down :toggle :cancel_task :reset :restart :all_on :all_off :open_related :copy
  :new :external :escape :leave …`, the list in `Keymap.SettingsBindings`).
- **In-page filter (D37).** `/` on a page of more than 20 focusable rows below the section
  level. A section's `filter(ctx, rows, query)` answers first (return nil to let the layer
  match the row text); U3's Key bindings can match key names this way.
- **Tasks** in `layer.tasks` are string-keyed maps (`"action" "target" "attributes" "state"
  "received_at_ms" "mine"`); `Tasks.cancellable?/1` is the client's list.
- **Loads.** A load the service cannot answer is asked once per arrival on a page (Ctrl-R and a
  `settings_update` ask again); what the open view brings (values, overview, facts, projects) is
  not asked beside it.
- **Overview** (`Sections.Overview`): `items/1` (the service's attention + AT13 + AT14, sorted)
  and `summary/1` (`%{changed, attention, env}`, the search row's strip on every page). Section
  `attention/1` callbacks are not consulted (see Deviations).
- **D11.** `Settings.ChatProvider.missing/1` reads the workspace's `chat_provider_usable` (S1's
  field) beside `chat_provider` (the name), or `chat_provider: %{name, usable}`.
- **Init/State.** `%Init{settings_open, prefs, launch_facts, resume_picker?}`;
  `State.pending_open_settings`, `State.pending_resume_picker`, `State.settings_history`,
  `State.key_overrides`, `State.launch_facts`.
- **Display.** A model value (`%{"provider_id", "model"}`) reads as its model id.

## Deviations (with the reason)

- Commit prefix `cli74 U1-n` (the orchestrator's rule), not §5.0's `pass74`.
- Editors keep their text in `Settings.Buffer`, not `FieldEditors` (a pure buffer the editors
  own; FieldEditors is keyed by the shell's field ids).
- ReadOnly, Action, Path and KeyValue are not separate editor modules: read-only and action rows
  have no editor, Path uses `Editors.Text` (`parse:` the entry), and key/value maps are U2's
  sub-pages (`KeyValueSecrets`), which an editor cannot express (secret values are paste targets).
- Extra fields: `Layer.next_ref`, `Layer.file_conflicts`, `Layer.watch_generation`,
  `Data.project_id`, `Data.conversation_id`.
- Extra bindings: `D` (delete a record), Esc/interrupt/edit/paste/popover ids, F2 also closes.
- The section reset is one undo step per value it resets, not one step for the section.
- `@cli`, `@session` and `@project` filter by the entry's scope; `@modified` leaves out read-only
  facts (the Overview counts the same set). The search index lists models and tools from record
  fields `"models"` and `"tools"`.
- `Sections.sub_rows/3` shows a sub-page opened with its rows (`{:rows, title, rows}`).
- The Overview's *changed from default* lists the strongest layers first (flag, env, session,
  project, cli.json, global), then rail order: F1's order is neither rail nor layer order and the
  spec does not fix it. Glance lines read whatever fields the service's fragment carries
  (`answered`, `never_tested`, `usable`, `chat`, `names`, `reader`, `connected`, `tools_off`,
  `each`, `sessions`, `cleanup_days`, `last_sweep`); unknown fragments print `key value` pairs.
- The Overview's attention list is the service's items plus AT13/AT14 only. Asking every section
  module's `attention/1` per frame went through the code server for each module a partial build
  lacks (60 s test timeouts), and the strip counts the list on every page.
- AT13 is not raised when the session keeps no cli.json (`{:error, :unavailable}`: the demo, a
  test); a failed write there says `this session keeps no cli.json (a demo or a test session)`.
- While the chat provider cannot answer, a blank open (F2, `/settings`) lands on Providers (the
  words say `F2 opens Settings › Providers`); an argument still wins. The §3.10.1 "header chip"
  is a fact on the status row (rank 88, kept on narrow screens), where the workspace's facts are.
- `resume_picker?` (S1's request) opens the resume picker once the shell is ready without
  clearing a restored draft; `swarmcode settings` wins over it.
- `plain/command.ex` and `one_shot.ex` were edited for the `/settings` words in `--plain` and
  `-p`; `feature_form_test` uses `:memory` after D22 removed the settings form.
- The pass-through `Keymap.Overrides` and `Keymap.KeyName` (published at `c74-U1-api`) will meet
  U3's versions add/add: take U3's. The Overview reads `Overrides.errors` as `[{binding_id,
  reason}]` (the published struct); if U3's shape differs, adjust `key_attention/1` in
  `settings/sections/overview.ex`.
