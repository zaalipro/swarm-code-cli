Fixes found by the gates (each with a focused test):

- `d63b3019` queue race (C1/pass70 Q3): `PersistedBackend.drain_queue/1` and `watch_queue/1` read
  the run registry twice; right after a turn's `DOWN` the registry can still list the dead pid,
  so the first read saw the turn (no pop) and the second did not (no monitor), and the queued
  prompt waited for ever. Found as `pass70_qa_queue_test` failing in precommit run 1; it failed
  alone 1 in 3, 1 in 6, 1 in 8 and 1 in 29 runs. Traced with events recorded in the backend
  state. After the fix: 40/40 runs alone.
- `86ad3180` demo PTY suite: E16's live-runs quit dialog says `Enter/X quit · Esc cancel`, so the
  suite's `CONFIRM EXIT` marker never came after the merge.
- `a5366f64` client codec: `DTO.CommandResult` had no optional wire keys, so every
  `rewind.turns`, `history.search`, `attachment.slot`/`attach_slot` and `rewind.apply` answer
  (the daemon names only its kind's fields) failed the exact-shape check and the client closed
  the connection. Found by the saved-session PTY suite (`/rewind` ended the session with "the
  daemon connection closed"); lane tests used `Fake` and backend calls, never the real codec.
  New `pass70_socket_test` case sends `rewind.turns` and `history.search` over the real socket.
- `0aea45fa` saved-session PTY suite: with the side panel auto (E5, Q8) a lone chat run draws no
  panel, and bare `/rewind` opens the turn list (D10), not the checkpoint report.
- `62d2e887` launcher: `usage()` printed its 4 KB help with `cat <<'HELP'`. Homebrew bash 5.3
  writes a here-document into a pipe when it fits the pipe size bash was built for; under macOS
  pipe-memory pressure new pipes hold 512 bytes, so `ncode --help` waited for ever (precommit
  run 3: LauncherTest and C74SettingsEntryTest timed out at 60 s while another app on this Mac
  held 1,327 pipes). It now prints one single-quoted string with the `printf` builtin; the
  output is byte-identical (`cmp`). New LauncherTest case: the launcher has no here-document.
- `95a96b3c` `persisted_backend_test` "run inspector pages older persisted message records":
  the expectation sorted `DateTime` structs by term order (microsecond before minute and
  second), so 45 inserts that crossed a second boundary under load expected the wrong page. The
  rows now get fixed `inserted_at` values 70 ms apart (three boundaries every run; watched
  failing) and the expectation sorts by `DateTime.to_unix(:microsecond)`.
- `0fb47f46` `fake_test` "each admitted query deadline returns its validated expected error page":
  missed ExUnit's default 100 ms `assert_receive` once under load (precommit run 5; passes alone).
  The client emits the failure synchronously while it handles `{:expired, token}`, so the test
  now syncs with `:sys.get_state/1` and uses `assert_received`. Not reproducible alone, so it was
  not watched failing; the change removes the timing assumption.

## Deviations (finisher)

- B23 `--approval`: the contract has OneShot pass the mode "into the dispatch". The send travels
  the socket, and the wire has no approval field, so the mode is a `PersistedBackend` start
  option (trusted launcher input, validated in `init/1`) that the backend adds to its
  `Engine.start_chat_turn` call and to `CommandDispatcher.dispatch` opts; the dispatcher
  (repinned) adds it to its chat and swarm launches. A chat `/goal` calls `start_chat_turn`
  itself when an override is set, because the synced `start_goal_turn/3` does not forward
  `approval_mode:`. Workflows, `/compact` and prompts drained from the queue keep the project's
  mode. The untrusted refusal reuses no desktop sentence (the desktop's `set_approval_mode` has
  none, as F's notes say): "--approval auto and full need a trusted project. Run /trust in
  ncode first, or use --approval read-only." (exit 3, and the `--json` not_started object).
- E9: nothing set `state.search_results`; the finisher added the field to `UI.State` (D's file)
  and the reducer clause that fills it from C8's rows and opens the palette on `?`. A `/search`
  with no hits stays the report.
- D's runtime guards (`Remote.send/3` checks `Request.validate/1`, `Remote.drawable?/1`,
  `Reducer.set_panel/2`'s `Preferences.valid?/1`) are kept: they are validation, not stubs, and
  every op and layer now passes them. Only the test branches and E's target guards were removed.
- AGENTS.md: F and G gave no CLI text; A's "Replace the pin-specific lines" text was merged into
  the schema invariant with the re-sync to `7b8f379f` added.
- The PTY suites ran under a scratch `HOME`, `NCODE_CONFIG_DIR` and an empty `SWARM_ENV_FILE`
  (`~/.cache/ncode/cli020/fin/pty-home`), with mise/mix/hex/cargo homes pointed at the real
  toolchain folders, so no suite read `~/.secrets` or wrote the real logs folder.
